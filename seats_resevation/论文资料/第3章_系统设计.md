# 第3章 系统设计

本章将在系统需求分析的基础上，对图书馆座位预约系统进行系统设计。首先设计系统的整体架构，明确各模块之间的关系与数据流向；然后进行数据库设计，设计用户、座位、预约等核心数据集合的结构；接着描述主要页面的功能设计；最后详细说明信用分机制的设计规则。

## 3.1 系统架构设计

### 3.1.1 整体架构

本系统采用微信小程序+云开发的BaaS（Backend as a Service）架构模式，整体架构分为客户端层、业务逻辑层和数据服务层三个层次[5]。系统架构图如下：

**（1）客户端层**：运行在微信客户端内部，包括小程序页面视图、业务逻辑处理和UI组件库三个部分。页面使用WXML编写视图结构，WXSS定义样式，JavaScript处理交互逻辑。Vant Weapp组件库提供了Picker、Popup、Button等70+高质量业务组件，显著提升了开发效率。

**（2）业务逻辑层**：由微信云函数组成，运行在云端的Node.js环境中。每个云函数独立部署，负责处理特定业务逻辑，如创建预约、签到确认、状态变更等。前端通过wx.cloud.callFunction()调用云函数，实现前后端分离。

**（3）数据服务层**：由云数据库集合组成，采用MongoDB风格的NoSQL数据库。本系统定义了users、seats、reservations三个核心集合，通过openid实现用户身份关联与数据隔离。

### 3.1.2 数据流转设计

系统的核心数据流转过程如下：

**用户登录流程**：用户打开小程序 → 调用getOpenId云函数获取openid → 查询users集合确认用户是否存在 → 若不存在则自动创建用户档案。

**座位预约流程**：用户选择座位 → 进入预约详情页 → 选择开始时间与时长 → 前端进行时间范围校验 → 调用createReservation云函数 → 云函数检测时段冲突 → 创建预约记录并更新座位状态。

**签到使用流程**：用户到达图书馆 → 扫描签到二维码或点击签到按钮 → 调用checkIn云函数 → 更新预约状态为checked → 座位状态保持occupied。

**状态自动过期流程**：用户进入首页时触发 → 调用autoExpireReservations云函数 → 查询pending状态预约 → 将超时15分钟未签到的预约状态改为expired → 扣除用户信用分 → 座位状态恢复available。

## 3.2 数据库设计

本系统使用云数据库作为数据存储介质，采用NoSQL数据模型。数据库中共包含users、seats、reservations三个集合，以下分别介绍各集合的结构设计。

### 3.2.1 用户集合（users）

用户集合用于存储注册用户的基本信息，包括openid、昵称、信用分、管理员标识等字段。users集合结构如下表所示：

| 字段名 | 类型 | 描述 |
|-------|------|------|
| _id | String | 文档ID，由数据库自动生成 |
| openid | String | 微信用户唯一标识，作为用户身份主键 |
| nickName | String | 用户昵称，默认值为"用户"+openid后4位 |
| avatarUrl | String | 用户头像URL，默认为微信默认头像 |
| credit | Number | 信用分，初始值为100，范围0-100 |
| isAdmin | Boolean | 是否为管理员，默认false |
| totalReservations | Number | 历史预约总次数 |
| checkInDays | Number | 连续签到天数 |
| lastCheckInDate | String | 最后签到日期，格式YYYY-MM-DD |
| createTime | Number | 注册时间戳，毫秒级Unix时间戳 |

### 3.2.2 座位集合（seats）

座位集合用于存储图书馆各楼层的座位信息，包括座位编号、所属楼层、座位类型、当前状态等字段。seats集合结构如下表所示：

| 字段名 | 类型 | 描述 |
|-------|------|------|
| _id | String | 文档ID |
| seatId | String | 座位编号，格式如"1F-001"（1楼001号） |
| floor | Number | 所属楼层，取值1/2/3 |
| type | String | 座位类型：collaboration（协作区）/quiet（安静区）/media（多媒体区） |
| status | String | 当前状态：available（空闲）/occupied（已预约使用）/maintenance（维护中） |
| position | Object | 座位位置坐标，{row: Number, col: Number} |
| description | String | 座位描述，如"靠窗"、"角落"等 |

### 3.2.3 预约集合（reservations）

预约集合用于存储用户的预约记录，包括预约的座位、预约时间、预约状态等核心信息。reservations集合结构如下表所示：

| 字段名 | 类型 | 描述 |
|-------|------|------|
| _id | String | 文档ID |
| openid | String | 预约用户openid |
| seatId | String | 预约座位编号 |
| date | String | 预约日期，格式YYYY-MM-DD |
| startTime | String | 开始时间，格式HH:mm |
| endTime | String | 结束时间，格式HH:mm |
| status | String | 预约状态：pending（待签到）/checked（已签到）/ended（已结束）/expired（已过期）/cancelled（已取消） |
| createTime | Number | 创建时间戳 |
| checkInTime | Number | 签到时间戳，未签到为null |
| endTime_ts | Number | 结束时间戳，未结束为null |
| duration | Number | 预约时长（分钟） |

### 3.2.4 集合索引设计

为提高数据库查询效率，在核心集合上建立了适当的索引：

**users集合**：在openid字段建立唯一索引，确保用户身份快速查询。

**seats集合**：在seatId字段建立唯一索引；在floor和status字段建立复合索引，支持按楼层和状态筛选座位。

**reservations集合**：在openid和date字段建立复合索引，支持查询用户某日预约；在seatId、date、status字段建立复合索引，支持座位时段冲突检测。

### 3.3.2 首页设计

首页是用户打开小程序后的第一个页面，承担着信息展示与功能导航的作用。首页布局自上而下分为三个部分：

**顶部轮播区**：使用Vant Swiper组件实现图片轮播功能。轮播图共2张，第一张为系统介绍图，标题"图书馆座位预约系统"，副标题"30分钟内即时预约，扫码一键签到"；第二张为图书馆实景照片，展示学习环境。轮播指示器位于底部居中。

**中部统计卡片区**：使用Grid网格布局展示三个统计指标——今日空闲座位数、今日预约总数、座位使用率。统计数据从云数据库实时查询计算得出，以卡片形式呈现，点击可进入相应功能。

**底部楼层入口区**：三个楼层入口按钮横向排列，分别对应1楼协作区、2楼安静区、3楼多媒体区。按钮使用圆角卡片样式，标注楼层名称与座位类型描述。点击按钮跳转至对应楼层的平面图页面。

### 3.3.3 楼层平面图设计

楼层平面图页面以Grid网格布局展示选定楼层的所有座位。每个座位以方块形式呈现，方块颜色表示当前状态：绿色表示空闲可用，灰色表示已被预约或使用中，橙色表示处于维护状态。

页面上方设置Tab标签页切换楼层，当前选中楼层高亮显示。座位网格下方显示图例说明，解释各颜色的含义。空闲座位可点击，点击后跳转至预约详情页并携带座位信息。

座位方块内显示座位编号，如"001"、"015"等。若座位处于被预约状态，方块上叠加显示预约用户昵称的首字。维护中的座位显示"维护"标签，无法点击。

### 3.3.4 预约详情设计

预约详情页用于用户确认预约信息并完成预约创建操作。页面分为上下两个区域：

**上部座位信息区**：展示选中座位的编号、所属楼层、座位类型等基本信息。座位编号以大号字体突出显示，下方以标签形式展示楼层与类型。

**下部时间选择区**：包含两个Picker选择器——开始时间选择器与时长选择器。

开始时间选择器的可选范围为用户进入页面时刻起30分钟内的时段，时间粒度为5分钟。例如，用户于14:25进入页面，则可选时间范围为14:30至15:00，每5分钟一档，共7个可选时间点。

时长选择器提供6个固定选项：30分钟、60分钟、90分钟、120分钟、150分钟、180分钟。默认选中30分钟。

时间选择完成后，页面实时计算并显示预约的结束时间。若用户选择的时间段与已有预约存在冲突，页面显示红色警告提示"该时段已被预约，请选择其他时间"。

确认预约按钮位于页面底部，点击后调用createReservation云函数创建预约记录。

### 3.3.5 我的预约设计

我的预约页面采用Vant Tabs组件实现今日预约与历史记录两个Tab页的切换。

**今日预约Tab**：展示用户当日的所有预约记录，按预约开始时间升序排列。每条记录以卡片形式展示，包含座位编号、预约时段、当前状态等核心信息。不同状态对应不同的操作按钮：pending状态显示"取消预约"和"签到"两个按钮；checked状态显示"结束使用"按钮；其他状态仅展示状态标签。

**历史记录Tab**：展示用户过往的预约记录，默认展示最近30天的数据。记录按日期分组，日期标题作为分隔符。每条记录显示座位编号、预约日期、预约时段、结束状态等信息。

签到功能支持两种方式：点击"签到"按钮直接签到，或扫描管理生成的签到二维码完成签到。后者通过wx.scanCode API实现，扫描成功后自动调用checkIn云函数。

### 3.3.6 个人中心设计

个人中心页面采用纵向列表布局，主要包含以下功能模块：

**用户信息区**：顶部展示用户头像与昵称，头像从微信获取，昵称可点击编辑。

**信用分展示区**：以圆形进度条形式展示当前信用分数值，下方标注信用等级——优秀（80-100分）、良好（60-79分）、较差（60分以下）。信用分低于20分时显示"已被禁止预约"的红色警示。

**统计数据区**：以Grid网格形式展示四项统计数据——连续签到天数、本周预约次数、本月预约次数、历史预约总数。数据从云数据库聚合查询得出。

**功能入口区**：以List列表形式提供操作入口，包括"预约规则"、"帮助与反馈"、"退出登录"等。预约规则以弹窗形式展示系统各项预约规定。

### 3.3.7 管理后台设计

管理后台面向管理员用户，提供系统管理与数据监控功能。页面采用Tab标签页布局，包含四个功能模块：

**座位管理Tab**：以与楼层平面图相同的Grid布局展示座位，支持按楼层筛选。管理员可点击座位将其设为维护状态或恢复正常状态。维护状态的座位在普通用户界面显示为橙色不可预约。

**用户管理Tab**：以列表形式展示所有用户信息，包括昵称、信用分、管理员标识等。管理员可调整用户信用分、设置或取消用户的管理员权限。

**数据统计Tab**：以卡片形式展示今日核心数据——今日预约总数、已签到数、已结束数、过期未签到数，以及全楼层座位使用率。

**二维码生成Tab**：提供签到二维码生成功能，管理员点击按钮后调用generateCheckinCode云函数生成二维码图片并展示，供学生扫描签到。

## 3.4 信用分机制设计

### 3.4.1 信用分体系概述

本系统设计了基于信用分的用户评价体系，通过量化用户行为引导用户守约使用[10]。信用分初始值为100分，取值范围为0-100分。信用分与用户权限直接挂钩：信用分低于20分时，用户将被禁止创建新的预约，需通过正常履约行为逐步恢复信用。

### 3.4.2 信用分计算规则

信用分的变化遵循以下规则：

**加分规则**：用户按时签到并完成使用后，信用分保持不变；系统设置连续签到奖励机制，用户连续7天按时签到可获得+1分奖励，奖励次数不设上限。

**扣分规则**：用户迟到（超过预约开始时间15分钟）签到扣10分；用户预约后未签到（预约时段过期）扣10分；用户在签到前取消预约扣5分。

信用分扣分阈值设置为20分，低于此分值将触发预约禁令。用户信用分被扣至20分以下后，需经过至少10次按时签到且未发生任何违约行为，系统才会将信用分恢复至20分并解除预约禁令。

### 3.4.3 信用分触发机制

信用分的变化由以下场景触发：

**预约创建时**：系统检查用户信用分是否大于等于20分，若低于20分则拒绝创建预约并提示用户。

**签到时**：checkIn云函数检测签到时间是否超过预约开始时间15分钟，若超过则扣除10分并将状态改为expired。

**取消预约时**：cancelReservation云函数检查预约创建至今是否少于5分钟，若超过5分钟则扣除5分。

**主动结束时**：endReservation云函数记录用户按时完成使用，连续签到天数+1。

**自动过期检测时**：autoExpireReservations云函数对超时未签到的预约执行过期处理，扣除10分。

### 3.4.4 信用等级划分

根据信用分数值，将用户划分为三个等级：

| 信用等级 | 分值范围 | 等级说明 |
|---------|---------|---------|
| 优秀 | 80-100分 | 守约行为良好的用户，享受正常预约服务 |
| 良好 | 60-79分 | 有少量违约记录的用户，需注意履约 |
| 较差 | 0-59分 | 违约行为较多的用户，预约权限受限或被禁用 |

信用等级仅作为展示用途，不影响实际功能权限。实际权限判断以20分阈值为准。

## 3.5 本章小结

本章详细阐述了图书馆座位预约系统的设计过程。

在系统架构设计中，采用微信小程序+云开发的BaaS架构，将系统划分为客户端层、业务逻辑层和数据服务层三层结构，明确了各层的职责与交互方式。

在数据库设计中，定义了users、seats、reservations三个核心集合的结构与索引，支撑起系统的数据存储需求。

在页面设计中，描述了7个主要页面的功能布局与交互设计，为后续实现阶段提供了明确的设计依据。

在信用分机制设计中，建立了初始100分、违约扣分、20分禁约的信用体系，通过量化评价引导用户守约使用。
