# 第5章 系统测试与分析

本章对图书馆座位预约系统进行全面的测试与分析。首先介绍测试环境与测试方法，然后对系统各核心功能进行功能测试，验证系统是否满足设计要求；接着进行兼容性测试与性能测试，最后对测试结果进行分析并总结系统的局限性。

## 5.1 测试环境与方法

### 5.1.1 测试环境

本系统的测试环境配置如下表所示：

| 类别 | 配置项 |
|-----|-------|
| 开发工具 | 微信开发者工具 |
| 调试基础库 | 3.14.2 |
| 云函数环境 | 微信云开发Node.js环境 |
| 测试设备 | 微信开发者工具模拟器 |
| 手机测试 | 小米11（Android 12）、iPhone 13（iOS 16） |

### 5.1.2 测试方法

本系统采用黑盒测试与白盒测试相结合的测试方法，主要包括以下几种：

**（1）功能测试**：对系统的各个功能模块进行测试，验证功能是否符合需求。主要采用黑盒测试方法，通过操作小程序界面触发业务流程，检查返回结果是否正确。

**（2）接口测试**：对云函数接口进行测试，验证前后端数据交互是否正常。通过直接调用云函数API，传入不同参数检查返回结果。

**（3）兼容性测试**：在不同设备、不同屏幕尺寸下测试页面显示效果与功能可用性。

**（4）边界测试**：针对时间选择、时长限制、信用分阈值等关键参数进行边界值测试，验证系统对边界条件的处理是否正确。

## 5.5 测试结果分析

### 5.5.1 功能达成情况

通过上述测试，本系统各项核心功能的正确性得到验证：

**预约功能**：十项校验逻辑全部生效，时间粒度控制精确，冲突检测算法正确，信用分门槛控制有效。

**签到功能**：迟到判定准确，信用分奖惩执行正确，扫码签到功能正常。

**状态管理**：预约状态流转正确，自动过期处理及时，座位状态同步准确。

**管理功能**：权限控制严密，数据操作安全，统计功能正确。

### 5.5.2 系统性能评价

系统性能测试结果表明，基于微信云开发的BaaS架构能够有效支撑座位预约业务的性能需求。页面加载时间、云函数响应时间均在用户可接受范围内。系统具备良好的响应速度与并发处理能力。

### 5.5.3 存在的局限性

尽管测试验证了系统核心功能的正确性，但仍存在以下局限性：

**（1）无实时推送机制**：微信小程序不支持WebSocket长连接，座位状态变更无法实时通知用户，用户需手动刷新页面查看最新状态。

**（2）登录方式单一**：系统仅支持微信登录，未集成学号密码等传统认证方式，对于非微信环境使用存在限制。

**（3）无离线缓存**：网络不佳时用户体验受限，系统未实现本地数据缓存与离线操作支持。

**（4）座位图静态**：楼层平面图基于固定坐标渲染，未实现根据实际座位状态的动态热力图展示。

**（5）无预约通知**：用户预约成功后无微信服务通知提醒，可能导致用户遗忘预约时间。

## 5.6 本章小结

本章对图书馆座位预约系统进行了全面的测试与分析。

在功能测试方面，通过设计详细的测试用例，对用户登录、座位预约、签到确认、取消结束、自动过期、管理功能等核心模块进行了测试，所有测试用例均通过验证。

在兼容性测试方面，系统在多种屏幕尺寸和微信基础库版本下均能正常运行。

在性能测试方面，页面加载时间与云函数响应时间均在用户可接受范围内，并发处理能力满足高校图书馆的实际使用场景。

测试结果表明，本系统各项功能符合设计要求，能够有效支撑图书馆座位预约的业务需求。同时，本章也客观分析了系统存在的局限性，为后续改进提供了方向。
